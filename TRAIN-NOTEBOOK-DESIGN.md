# UX review 2 — training notebook boundaries

The commission authorizes a new Train/history workflow; Learn and movement
programming are retained. Existing V33 storage keys, Web Lock, stale-write guard
and journaled state/draft transaction remain authoritative.

- The engine owns prescriptions and recovery. Notebook presentation never invents
  successful exposures to forecast advancement. Lookahead is an ordered,
  provisional view at current evidence/loads, not a fixed calendar or a guarantee
  that recovery/prerequisites will be satisfied on a future date.
- Normal versus adjusted plans and reasons are stored separately from actual
  sets. Short duration uses the existing whole-movement fitting and deferral rules;
  low readiness uses existing configurable reductions without advancement credit.
  Feeling great preserves the planned progression, adding no automatic work.
- Prefill is a written prescription, not evidence. Only explicit final confirmation
  records all non-skipped work. A partial finish records explicitly completed work
  only. Timers never complete a set. Actual get-up counts cannot be inferred from
  elapsed seconds and must be entered. Cadence/continuous/both-side completion is
  explicitly self-reported at final confirmation, never skill certification.
- New drafts opt into variable actual set counts with notebookVersion 1. Legacy
  drafts retain strict existing shape. Added/removed sets do not change prescribed
  targets. Changes to actual rest/interval deny advancement credit.
- Corrections retain immutable recorded prescriptions plus append-only previous
  versions and last-edited timestamps. Undo appends a restoration version. Legacy
  summaries lacking set data are not reconstructed as invented exact sets.
- Progression and practice eligibility replay history already. Corrections rebuild
  block-specific unfinished queues and withdraw affected pending next-load
  choices; they do not erase deliberate skills, recovery settings or history.
  Newly introduced pain is not covered by an old pain resolution.
- Warm-up pattern priming is supported by source #670. The explicit preparation
  doses, gentle cooldown and UI timing are Strength Lab defaults, not claims of
  a source-prescribed universal routine. They use known session movements and
  available equipment, and introduce no unconfirmed advanced skill practice.

Implementation/test results and pending limitations are recorded in the log.
